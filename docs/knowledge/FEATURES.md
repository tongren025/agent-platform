# Agent Studio 业务功能大全

核对日期：2026-09-20。本页先检索项目知识库和业务手册，再针对易混淆的节点、字幕、配音、导出、评分及知识检索范围核对实际入口。描述的是当前提交可支持的能力；线上是否已部署、配置是否齐全、生成是否达标，需要分别验证。

## 现在有哪些功能：业务全景

系统围绕“创意 → 剧本 → 人物/场景 → 分镜 → 提示词 → 图片 → 镜头视频 → 审片返工 → 合成与下载”组织制作。

| 用户目标 | 主要入口 | 可以得到什么 |
|---|---|---|
| 做一部约 3 分钟的短片 | 我的项目 `/production`、快速制作 `/studio` | 单集 180 秒项目规格、分镜、逐镜素材、审片和成片候选 |
| 制作系列短剧 | 项目设置、制作看板、单集详情、链路矩阵 | 按季/集/镜头管理的制作资料与素材 |
| 手机记录灵感并做小视频 | `/mobile` | 导演对话、15/30 秒竖屏项目、逐镜确认 |
| 在画布中组织素材和初剪 | `/canvas` | 文稿、人物场景参考、生成节点、媒体与文字时间线；网页最终导出见边界说明 |
| 找专门岗位处理一个任务 | `/workbench`、`/employees`、`/teams` | 员工或团队对话、工具执行与创作产物 |
| 把流程做成重复使用的 SOP | `/workflows` | 配置好的节点流程、执行结果与运行记录 |
| 为员工补充资料与经验 | `/learning`、`/memory`、员工参考资料 | 知识文件、学习摘要、长期记忆与改进建议 |
| 管理模型、权限与运行 | `/settings`、`/models`、`/tasks`、`/runs`、`/admin` | 配置、状态、错误线索、配额与权限管理 |

新作品没有已有草稿时，项目向导默认原创创意、1 集、180 秒、9:16、完整成片；旧草稿和系列项目设置保留。当前主要制作页面统一为暖白内容区、深墨媒体区和铜色操作按钮，项目卡与首页的“已有成片”依据后端真实媒体标记。

## 怎样阅读能力状态

- **主站功能**：已有页面或业务 API；菜单是否可见仍受角色权限影响。
- **需要配置**：模型、密钥、员工岗位、远程服务或任务 worker 就绪后才能执行。
- **制作规范**：提示词、岗位交接与审核要求；不是模型每次都能自动达标的保证。
- **部分接入**：例如画布具有字幕/音轨编辑，但网站最终渲染导出尚未形成同一条完整链路。
- **接口/引擎能力**：后端存在，不代表当前可视化编辑器提供全部操作按钮。

## 一、入口和制作组织

| 编号 | 入口 | 具体能力 | 输入 → 输出 | 限制与业务说明 |
|---|---|---|---|---|
| P01 | 今日制作 `/dashboard` | 查看重点项目、当前阻塞、正在运行任务、推荐下一步 | 已有项目和运行状态 → 继续制作入口 | 推荐下一步不代表已自动执行 |
| P02 | 快速制作 `/studio` | 按一个明确交付目标推进单条制作主线 | 创意与目标 → 阶段进度、下一步按钮 | 需要已启用岗位和对应模型 |
| P03 | 我的项目 `/production` | 列出有权访问的项目、卡片数、进度 | 用户身份 → 项目列表 | 项目成员与全局权限都会影响可访问范围 |
| P04 | 项目总览 `/production/:pid` | 打开同一个项目继续制作 | 项目 ID → 项目详情、集和素材状态 | 不需要重新创建同名项目 |
| P05 | 制作流水线 `/production/:pid/pipeline` | 按生产阶段组织卡片 | 项目卡片 → 阶段看板 | 看板状态与媒体通过验收是不同信息 |
| P06 | 单集详情 `/production/:pid/ep/:ep` | 聚焦指定集的镜头、素材与评审 | 项目和集数 → 本集制作内容 | 适合逐集推进，不要求一次跑完整季 |
| P07 | 完整性检查 `/production/:pid/matrix` | 看阶段链路、缺失与阻塞问题 | 项目与目标 → 缺口、健康分、动作 | 健康分是规则评分，不是观众喜爱度 |
| P08 | 画布中心 `/canvas` | 打开挂载的无限画布工作台 | 项目、集、G 镜头 → 创作/生成/预览工作区 | 当前路由挂载 CanvasHub 和 third_party/nomi；遗留 Canvas.tsx 不是当前主入口 |
| P09 | 灵感随手拍 `/mobile` | 手机轻量创作与逐镜确认 | 一句话、可选参考图 → 15/30 秒竖屏项目 | 当前手机入口不是 3 分钟短片的完整精剪入口 |
| P10 | 找数字员工帮忙 `/workbench` | 单独向导演、编剧、设计、分镜、媒体或质检岗位提问 | 用户说明、附件、上下文 → 对话与工具结果 | 普通对话出图与项目卡片交付不是完全相同的写回链路 |
| P11 | 系统帮助 `/guide`、问号/系统管家 | 使用手册、术语提示、重播引导与故障指路 | 当前页面/问题 → 使用说明或诊断 | 引导展示不代表后台已完成制作 |

| P18 | 项目创建/设置 | 记录预算 | budget → 项目预算字段 | 这是保存预算数据，不能宣称全流程自动成本结算或保证不超预算 |
| P19 | 项目列表/设置 | 设置项目置顶并继续原进度 | pinned → 首页/列表优先项目 | 置顶只是组织方式 |
| P20 | 项目设置 | 部分修改项目信息 | 指定字段 → 更新后的项目 | settings 使用合并语义，非整对象覆盖 |
| P21 | 项目成员接口/协作界面 | 添加成员、修改角色、移除成员 | 用户 ID、项目角色 → 成员列表 | 不允许删除或降级最后一个 owner |
| P22 | 项目卡片批注 | 添加文字批注 | 卡片 ID、意见 → 带真实作者的批注 | 作者由鉴权身份确定 |
| P23 | 项目批注面板 | 过滤卡片批注、查看未解决/全部批注 | 卡片筛选、包含已解决开关 → 批注列表 | 批注不是自动执行的返工任务 |
| P24 | 项目批注面板 | 标记解决或重新打开批注 | resolved → 批注处理状态 | 解决批注不自动等于媒体通过验收 |

## 三、剧本、人物、场景和视觉母版

| 编号 | 入口 | 具体能力 | 输入 → 输出 | 限制与业务说明 |
|---|---|---|---|---|
| P25 | 快速制作/创作区/编剧员工 | 将故事想法扩为剧本阶段卡片 | 原素材、项目目标、补充要求 → 场次、动作、对白等正文 | 是生成能力；剧情是否打动人仍需要编辑审稿 |
| P26 | 阶段生成 | 指定目标阶段和执行员工 | target_stage、employee_key → 对应岗位产物 | 无可用岗位或缺前置内容会报错，不应伪装生成成功 |
| P27 | 阶段生成 | 追加内容或定向替换 | append/replace、集数、G 单元 → 新增或替换卡片 | 定向替换应限定当前阶段/集/镜头 |
| P28 | 编剧提示词规范 | 引导开场钩子、人物目标、阻力升级、转折、情绪落点 | 项目故事 → 更完整的商业短片叙事稿 | 这是提示词合同，不是“保证抖音爆款”的算法 |
| P29 | 人物设计岗位 | 生成角色身份、服装、比例、表情及状态文字规格 | 剧本/人物要求 → 人物设定卡 | 首次设计不要求先拥有母版图 |
| P30 | 场景设计岗位 | 生成空间、材质、光线、时段、方向和场景功能规格 | 剧本场景 → 场景设定卡 | 场景文字规格和真实场景图分别生产 |
| P31 | setting 阶段协作 | 无单独指定时协调人物与场景两岗 | 故事与设定要求 → 两类设定产物 | 两岗先做可用性校验，全部成功才落卡；失败不先清空旧卡 |
| P32 | design 阶段/画布风格步骤 | 建立风格文字母版 | 画风、色彩、光影、材质、画幅 → 设计/风格卡 | 默认文字设计不等于已经生出母版图 |
| P33 | 角色生成岗位/画布人物步骤 | 根据角色规格生成人物参考图 | 已审核角色提示和模型 → 图像资产 | “三视图/表情集”是图像生成目标，不是确定性 3D 角色建模 |
| P34 | 场景生成岗位/画布场景步骤 | 根据场景规格生成可重复引用的场景图 | 场景提示和模型 → 场景资产 | 不保证跨次生成像素或几何完全一致 |
| P35 | 下游上下文交接 | 传递真实素材地址、状态、资产版本、镜头标识 | 上游卡片/媒体 → 下游制作上下文 | 有素材不代表素材已经通过视觉质量验收 |
| P36 | 单镜返工 | 保留全局角色/场景参考，限定当前集和镜头 | 当前问题、全局母版 → 单镜修正产物 | 不应把其他集剧情混入当前返工 |
| P37 | 生产合同 | 记录必要假设和阻塞项 | assumptions/blockers → 可追溯制作说明 | 非空 blockers 不应显示静态质量已通过 |

## 四、分镜、镜头动态和提示词

| 编号 | 入口 | 具体能力 | 输入 → 输出 | 限制与业务说明 |
|---|---|---|---|---|
| P38 | 分镜岗位/画布第 6 步 | 把剧本拆成逐镜计划 | 剧本、人物、场景 → 镜头方案与分镜卡 | 先规划，再确认生成，不应只见一段回复就算节点已建好 |
| P39 | 分镜方案编辑器 | 审核和修改分镜方案后提交 | 草案 → 用户确认方案 | 方案未提交时再次操作应打开编辑器，不重复付费生成 |
| P40 | 分镜制作规范 | 明确景别、机位、主体、前中后景、画面位置、视线/轴线 | 每镜剧情 → 可拍/可生成的空间描述 | 字段齐全不代表画面构图必然正确 |
| P41 | 镜头动态设计 | 区分人物动作路径与相机运动 | 镜头起止状态 → 动作/运镜/节奏描述 | 固定机位也需要明确说明 |
| P42 | 起止姿态与承接 | 描述起始姿态、分时动作、结束姿态及相邻镜衔接 | 当前与相邻镜头 → 连续性要求 | 当前系统提供要求和评审，不保证模型动作自然 |
| P43 | 分镜拆卡接口 | 将带“镜头 N”段落的分镜卡拆为逐镜故事板 | 可识别格式的分镜正文 → 多个故事板单元 | 依赖格式，不能任意正文无损自动拆分 |
| P44 | 图片提示词阶段 | 生成风格、主体、静态姿态、构图、光影、情绪和画质要求 | 分镜、母版 → 可提交图片提示词 | 图片提示要描述瞬间，不把台词/时间变化当画面 |
| P45 | 视频提示词阶段 | 生成动作、运镜、时间段、声音、对白与连续性要求 | 分镜、首尾帧和控制说明 → 视频提交提示 | 模型支持和可执行时长仍以供应商接口为准 |
| P46 | 导演台/卡片详情 | 保存当前镜头主图片提示词微调 | 用户修改 → 主提示词更新 | 保留其余提示词和生产元数据，不重写整个项目 |
| P47 | 生产静态门禁 | 检查分镜必填项、抽象画面词、负向表达、运动风险等 | 文本规格 → 明确问题与修改方向 | 是确定性规则，不调用模型去判断真实像素 |
| P48 | 提示词资产库 | 查看内置人物、场景、分镜专业模板 | 类别 → 方法模板与提示词资产 | 模板需要结合当前项目填写 |
| P49 | 采用后学习 | 把用户确认的提示词记录为案例 | project/employee/items → 案例库与对应员工记忆 | 采纳代表用户选择，不自动证明所有生成效果都高质量 |
| P50 | 提示词/文章学习页面 | 引入参考案例和导演/摄影/叙事知识 | 学习源或材料 → 可检索知识/记忆 | 未筛选案例可能带入不合适风格，应选择已验证样片 |
| P51 | 《九陆纪元》专用提示词标准 | 定义 G 单元、4–6 秒子段和提示词文本格式 | 指定项目卡池 → v3 格式化产物 | 项目专用脚本与规范；不能据此宣称所有项目都自动子段接力生成/末帧提取 |

## 五、镜头控制、素材和媒体生成

| 编号 | 入口 | 具体能力 | 输入 → 输出 | 限制与业务说明 |
|---|---|---|---|---|
| P52 | 导演台模型选择 | 从执行员工配置读取图片/视频模型 | 岗位配置 → 可选媒体模型 | 无可用凭据/模型时不能用文字模型冒充媒体服务 |
| P53 | 单镜控制包 | 选择自动、关键帧、参考图生成模式 | generation_mode → 镜头生成计划 | 首尾帧模式与普通参考图模式按合同互斥 |
| P54 | 单镜控制包 | 设置对白、表演、动作、运镜、建立环境、转场等镜头类型 | shot_type → 控制上下文 | “转场镜头”类型不等于后期有转场效果编辑器 |
| P55 | 单镜控制包 | 绑定首帧和可选尾帧 | first_frame_url/last_frame_url → 生成约束 | 人物三视图不能直接当干净视频首帧 |
| P56 | 参考素材上传 | 上传图片、视频、音频参考并绑定用途 | 文件、role → 镜头控制素材 | 音频参考不是 TTS，也不是保证口型克隆 |
| P57 | 参考素材分类 | 区分身份、表情、场景、道具、分镜、表演、运动、相机、站位、对白、声音、连续性、风格 | URL、类型、角色、优先级、备注 → 可解释引用表 | 每个素材用途需正确；控制包最多 30 条参考声明 |
| P58 | 镜头方案控制 | 保存 storyboard/camera/performance/audio/continuity 计划 | 五类文字控制 → 镜头控制包 | 控制计划最终落实程度要看生成与人工验收 |
| P59 | 单卡立即生图 | 使用默认主提示或显式修改稿生成图片 | 模型、提示、尺寸 → 本地图片候选 URL | 新图先作为候选，不能无条件替换已通过旧图 |
| P60 | 导演逐镜生图 | 将关键帧岗位模型与镜头图绑定 | 镜头和模型参数 → 图片卡、候选、生成信息 | 同期卡片变化时结果不应覆盖新状态 |
| P61 | 视频提交 | 用提示、首帧/尾帧/参考素材提交镜头视频 | 时长、分辨率、画幅、生成声音开关 → 异步 job | 提交成功不等于视频完成 |
| P62 | 视频轮询同步 | 查询上游 job，完成后下载 MP4 并写回 | job ID → 当前状态、文件 URL、卡片 | 依赖供应商完成；任务不存在、上游异常会返回错误 |
| P63 | 过期结果保护 | 比较媒体输入与当前卡片状态 | 输入指纹、任务结果 → 生效/过期标记 | 老任务完成不能覆盖已经改过的新镜头 |
| P64 | 卡片文件上传 | 手工上传图片/视频到指定生产卡片 | file_type、文件 → 卡片媒体列表 | 上传存在不代表已通过商业质量验收 |

## 六、质量验收、返工与项目诊断

| 编号 | 入口 | 具体能力 | 输入 → 输出 | 限制与业务说明 |
|---|---|---|---|---|
| P70 | 图片预览/卡片抽屉 | 对具体图片通过或退回 | 候选图、结论、原因、备注 → 评审历史 | 评审针对具体版本，不能只按卡片标题判断 |

| P79 | 单问题定向返工 | 调用当前阶段岗位修复可自动处理的文本问题 | issue_id、必须保留要求 → 对应范围新稿 | 一次只解决一项；历史仅 review 无明确失败原因要人工确认 |
| P80 | 缺失内容补写 | 对缺失阶段采用 append | 明确缺口 → 新阶段卡片 | 不应删除其他集或其他阶段 |

| P82 | 跨项目问题反馈 | 聚合高频问题、低健康项目、处理和成功情况 | 有权项目数据 → 反馈列表 | 是生产问题统计，不是平台播放量/观众数据 |

## 本次核验纠正的易误解点

1. 工作流可视化编辑器当前开放 7 种节点；后端引擎扩展能力与页面操作范围分别列明。
2. 员工知识上传默认是 .txt/.md，不按界面中“.pdf 等”文字直接承诺 PDF 解析。
3. 设置页运行参数与功能开关是只读展示，不是全项在线修改界面。
4. Skill/工具注册信息、完整技能包安装、真实工具执行是三个层次；仅新增名称不会生成业务执行能力。
5. 进化中的技能/工具建议采纳不自动安装资源；真正自动落地的是提示词追加与行为规则写入。
6. 趋势画像与已读数据当前按部署共享，不能宣传为各登录账号独立画像。
7. 员工能力图展示配置关系，不能当作剧情人物图或全文知识实体图。
8. /runs、/tasks、工作流历史、视频供应商状态分别服务不同执行路径，不能称为已统一覆盖全部生产任务的任务中心。
9. 成本字段和免费模型标签用于辅助判断，不代表供应商最终结算或无条件免费使用。
10. 工程知识库、站内手册、员工资料/记忆和系统管家没有默认全部自动互通。
