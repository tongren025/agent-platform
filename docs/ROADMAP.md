## 0. 定位与判断标准(先立规矩)

**一句话定位**:用 AI 数字员工把竖屏漫剧的生产工业化——一个人 = 一个工作室,质量稳定可复制。

**主从关系**:作品(《九陆纪元》)是目的,平台是杠杆,推广是副产品。顺序不可倒。

**北极星指标**:单集成片周期。

**一切功能的取舍标准**:能不能让下一集成片更快、更稳、更省?不能 → 不做。

## 1. 总目标(一年后的样子)

**作品线**
- 2026-Q4:《九陆纪元》S1 十集全部成片,抖音/B站/小红书发布,跑出数据。
- 2027-Q2:S2 过半;单集周期 ≤ 3 天;形成"概要进、成片出"的标准作业程序(SOP)文档化。

**平台线**
- 平台支撑 3-5 人协作生产,新人半天上手(靠文档四层体系 + 任务视图)。
- "剧本 → 成片"全链路在平台内闭环(现状:成片环节在平台外)。
- 一致性体系(Art Bible → 知识库 → QA 巡检 → eval 回归)全自动运转。

**商业/生态线**
- 作品发布时平台同步开源亮相("这部剧就是它产的"),吃一波作品流量。
- 2027-Q2 做商业化方向决策(见 §6),在此之前**不投入**商业化开发。

## 3. 需要优化(已有但不够好)

> 格式:现状 → 问题 → 动作 → 验收标准。按对北极星的影响排序。

### 3.1 LLM 调用韧性——仅剩旁路(主链路已完成)
- **现状**:agent 主链路已落地(`app/runtime/loop.py` `_create_with_retry`:超时+指数退避重试+同供应商换模型+跨供应商 fallback,且已迁 AsyncOpenAI 真并发);**仅剩两条旁路仍同步裸调**:画布生图 `app/api/canvas.py` 与网页总结 `app/services/scraper.py`。
- **动作**:两条旁路复用 loop.py 的重试封装或同等策略。
- **验收**:拔网线测试,画布生图与文章学习能干净失败可重试。

### 3.2 队列任务的可恢复性
- **现状**:arq 任务有状态查询,但整集批量任务中断后只能整体重来。
- **问题**:一键整集草稿(§4.1)一跑 30+ 卡,坏在第 20 张等于全废。
- **动作**:任务分片(每卡一个子任务)+ 断点续跑 + 失败卡单独重试按钮。
- **验收**:kill worker 后重启,已完成卡不重跑。

### 3.3 检索质量
- **现状**:向量检索纯余弦,无 rerank;知识库只吃 txt/md;混合检索(关键词+向量融合)没做。
- **问题**:知识库过千 chunk 后召回会掉;PDF 设定集进不来。
- **动作**:①bge-reranker(DashScope 有托管)重排;②RRF 融合关键词与向量;③PDF/docx 解析入库。
- **验收**:自建 20 条检索评测对(问题→应命中片段),top3 命中率 ≥ 90%。
- **时机**:2026-Q4(知识库真上量之后,勿提前)。

### 3.4 告警(M6 只有面板没有告警)
- **现状**:错误率飙升/队列积压/供应商连挂,无人知晓。
- **动作**:Grafana alert 三条:5xx 率 >5%(5min)、队列积压 >50、LLM 失败率 >20%;通知到钉钉/飞书 webhook。
- **验收**:手动制造故障,10 分钟内收到通知。

### 3.5 evals 从骨架到门禁
- **现状**:3 个 golden case,手动跑。
- **问题**:员工提示词会持续调优,没有回归网会越调越坏(已发生过蒸馏模板事故)。
- **动作**:每个生产主力员工 ≥3 个 case(共 30+);改员工提示词的 PR 必须附 eval 通过截图;接入 CI(需 LLM key 的用 secrets)。
- **验收**:任一员工提示词变更,10 分钟内知道有没有退化。

### 3.6 SSE 流式输出
- **现状**:对话/派生靠轮询,长任务盯转圈。
- **动作**:工作台对话 + 画布派生改 SSE;运行状态推送。
- **时机**:团队第 2 人进来之前(2026-Q4)。

### 3.7 生产配置固化
- **现状**:`ADMIN_SECRET` 未配(重启全员登出)、`modelPrices` 未配(成本列空)、`USE_DB_STORES` 未开、PG 全链路只在 SQLite 验证过。
- **动作**:.env 固化密钥 → 配价目 → docker compose 起 PG → alembic upgrade → 导入历史 JSON → 开开关 → 全量回归。
- **验收**:重启不掉登录;运行记录显示真实成本;PG 模式跑 118 测试全绿。

### 3.8 画布规模体验
- **现状**:看板导入单次 ≤60 卡;大画布节点多时性能未测。
- **动作**:200 节点压测;虚拟化渲染或分页导入;小地图导航。
- **时机**:实际卡了再做(先记录,不预支)。

## 4. 还需要做(新建设,按季度排)

### 2026-Q3(7-9 月)主题:「EP02-05 打样,全链路闭环」

#### 4.1 一键整集草稿 ⭐ 最高优先
- **内容**:选定 EP 概要卡 → 编排链(剧本 → 镜头拆分 → 逐镜脚本 → 分镜 → 图片提示词 → 视频提示词)→ 整集入队生成 → 产出完整制作包草稿(对标 EP01 的 30 卡结构)。
- **实现要点**:复用画布派生的 `STAGE_INSTRUCTIONS` 与员工链;走 arq 队列分片(见 §3.2);生成完成后钉在层级视图上待人工审。
- **验收**:EP02 概要进 → ≤2 小时出全套草稿 → 人工修订量 <40%。
- **预估**:后端 3 天 + 前端 2 天。

#### 4.2 素材批量回传
- **内容**:半自动出图路径(小云雀/即梦)的回程自动化——按命名约定(`EP02_S03_v1.png` → EP02 shot03 卡片)批量拖拽上传自动归位;不匹配的进"待认领"列表手动指派。
- **验收**:20 个镜头的图+视频,回传挂卡 ≤5 分钟(现状约 40 分钟)。
- **预估**:2 天。

#### 4.3 QA 自动巡检
- **内容**:qa-inspector 员工定时/手动扫指定集的提示词卡:Art Bible 违禁词、角色固定描述词缺失/漂移、必填字段缺失、镜头时长规格(4-5s 生成单元);产出巡检报告卡 + 违规卡片打标。
- **验收**:EP01 现有 30 卡跑一遍,与人工检查结果对照,查全率 ≥90%。
- **预估**:2-3 天(fix_card_violations 脚本已有雏形,产品化)。

#### 4.4 成本与周期打点
- **内容**:配 modelPrices;看板加"本集耗时/成本"统计条(从卡片创建到成片状态的时间差 + 关联 run 成本汇总)。
- **验收**:EP02 结束能报出:周期 X 天、成本 Y 元、返工 Z 卡。

### 2026-Q4(10-12 月)主题:「成片闭环 + S1 发布 + 团队化」

#### 4.5 成片装配线 ⭐

## 7. 明确不做(负面清单,一年内有效)

- **多租户/K8s/微服务拆分** —— 单机 compose 撑 5 人绰绰有余;触发条件见 §6 才重新评估
- **重造图像/视频生成器** —— 出图永远"半自动为主、API 为辅",平台价值在编排与一致性
- **泛化成通用 agent 平台** —— 不跟 Dify/Coze 抢赛道,垂直定位不动摇
- **买星/互刷等虚假增长** —— 一眼假,毁信誉
- **为推广而做的功能**(插件市场、开放平台等)—— 星和用户是作品的副产品
