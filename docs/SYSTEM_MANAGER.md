# 系统管家用户手册

系统管家是 Agent Studio 的全局帮助与能力管理入口。登录后，在任意用户页面点击右下角的紫色管家按钮即可打开。

## 它能做什么

- 识别当前页面，解释页面用途并给出下一步。
- 盘点数字员工、Skill、工具和 MCP，提示缺配置或缺登录的连接。
- 读取最近失败的 Agent 运行记录，解释错误而不是让用户自己翻日志。
- 对复杂产品问题，使用 `Agent.SystemManagerModel` 指定的专用模型结合当前页面状态、
  最近对话、当前操作对象和本地手册生成解释；未指定时才回退到平台第一个可用模型，
  抽屉标题会显示本轮真实模型引用；
  模型只有说明权限，不能直接安装、删除、登录或修改资源。
- 对 MCP 发起真实连接验证，并展示发现的工具数量。
- 从公开 GitHub 仓库检查、安装、更新或卸载标准 `SKILL.md` 技能包。
- 从对话中的服务 URL、官方安装命令或 JSON 配置创建 MCP。
- 通过标准 OAuth 浏览器授权登录远程 MCP，并加密保存本机令牌。
- 保存当前用户的管家对话和结构化焦点，因此“把它改名为…”“继续测试刚才那个 MCP”
  能指向上一轮对象；记录并可回滚由系统管家完成的配置变更。

## 常用问法

- `这个画布怎么用？`
- `告诉我下一步。`
- `检查系统状态。`
- `解释最近失败。`
- `安装这个 Skill：https://github.com/组织/仓库/tree/main/技能目录`
- 在管家里上传包含 `SKILL.md` 的 ZIP
- `卸载 Skill：example-skill`
- `添加 MCP：https://example.com/mcp，需要 OAuth 登录`
- `添加 MCP：https://mcp.notion.com/mcp，名称叫我的 Notion 知识库`
- `把它的名字改成内容知识库`
- `添加 MCP：npx -y @scope/example-mcp`
- `添加 MCP {"serverCode":"demo","name":"Demo","transportType":"stdio","command":"demo"}`
- `把 Skill generate-shots 绑定给员工 comic-director`
- `登录 MCP example-com`
- `验证 MCP example-com`
- `回滚 change_xxxxx`

## 安装 Skill

把公开 GitHub 仓库或具体 Skill 子目录链接发给系统管家，并明确说“安装”或“导入”。管家会先下载到临时目录、检查归档路径和 `SKILL.md` 清单，再显示安装预览。只有点击“确认执行”后才写入系统技能目录。同名 Skill 会进入更新流程；卸载前先检查员工绑定关系并备份目录。

如果一个仓库含多个 Skill，请提供指向具体目录的 `/tree/分支/目录` 链接。安装过程不执行包里的脚本，也不自动绑定数字员工；可以在检查完成后直接对管家说“把这个 Skill 绑定给某员工”。

也可以上传本地 ZIP。上传阶段只做大小、文件数量、路径穿越、可执行脚本与高权限工具
声明检查，并生成安装预览；仍需点击确认才写入技能目录。公开 GitHub 下载在服务器已
配置 `GITHUB_TOKEN` 时会自动使用它；令牌具备相应仓库读取权限时也可导入私有仓库，
且不会把 Token 写进会话或审计。没有仓库令牌时可直接上传私有 ZIP。

## 添加和验证 MCP

MCP 配置支持 `stdio`、`http`、`streamable_http` 和 `sse`。可以直接发送服务 URL、
官方 `npx` / `uvx` / `python` / `node` 安装命令，管家会推导基础配置；复杂配置仍可
发送 JSON。密钥不得直接写入对话或注册表，使用环境变量引用：

```json
{
  "serverCode": "example",
  "name": "示例 MCP",
  "transportType": "stdio",
  "command": "example-mcp",
  "env": {
    "API_TOKEN": "${EXAMPLE_API_TOKEN}"
  }
}
```

保存前会显示变更预览。保存后点击 MCP 右侧的“验证”，系统会真实建立会话并读取
工具列表；环境变量缺失、命令不可用或网页登录失效都会返回明确错误。
最近一次真实验证的时间、成功/失败、工具数量和无凭证错误摘要会保留，供后续排障。

从 URL 或包名推导时会去掉 `mcp`、`server`、`api`、顶级域名等技术噪声，预览中同时
显示名称和稳定 `serverCode`。名称不合适时无需重发配置，直接在同一会话说“名字改成
X”；未确认的旧预览会失效并生成新预览，已安装 MCP 则只修改显示名称，不改变编码、
连接、登录令牌或员工绑定。

当 MCP 声明 `authType: "oauth"` 时，卡片会显示“登录”。平台跳转到服务方授权页，
回调到 `/oauth/callback` 后交换令牌并立即验证工具发现。OAuth code 不落盘，访问令牌
使用平台本地密钥加密保存；可以从管家退出登录并清除令牌。

## 会话与回滚

系统管家会为当前登录用户保存对话、当前资源焦点和未确认 MCP 草稿，浏览器刷新后
自动恢复。模型回答会收到最近 16 条对话和结构化会话状态；会话记录会遮盖常见密钥
字段，不保存 OAuth code 或 token。

可在 `appsettings*.json` 中固定管家模型：

```json
{
  "Agent": {
    "SystemManagerModel": "provider:model-id"
  }
}
```

留空时兼容旧配置，回退到第一个可用模型；界面会用橙色标签明确提示这是回退模型。

安装、更新、卸载 Skill，添加/删除 MCP 和修改员工绑定成功后都会产生 `changeId`。
点击“回滚这次变更”只会生成回滚预览，仍需再次确认才执行。Skill 更新/卸载使用目录
备份恢复，注册表资源使用变更前 JSON 快照恢复。

Skill、内置工具和 MCP 都可以通过自然语言绑定或解绑数字员工。具体生产项目页面会
读取项目真实诊断结果，因此“下一步”会结合健康分、阻塞问题和交付目标回答。

## 安全边界

- 页面说明、资源盘点和连接验证属于只读操作，可直接执行。
- Skill 安装和 MCP 保存必须二次确认，提案 15 分钟后失效且只能使用一次。
- 删除、更新和回滚同样必须二次确认；回滚只允许原操作用户发起。
- 所有系统管家写接口要求当前用户具备现有的 `tool:manage` 权限。
- GitHub Skill 限制为 10 MB、500 个文件，并检查路径穿越。
- MCP 敏感字段只允许通过 `.env` 环境变量引用，OAuth 令牌加密保存。
- 变更日志位于 `data/system-manager/audit.jsonl`，会话和快照位于同目录下的隔离子目录；
  它们不保存密钥和 OAuth code。

## 协议边界

- OAuth 授权页和账号权限由对应 MCP 服务提供；平台只处理标准发现、PKCE、回调交换和
  本机令牌保存。非标准 OAuth 服务仍需要专用适配。
- Skill 只能声明依赖 code；上游没有提供依赖来源时，管家会列出缺项，不会猜测来源
  或静默执行依赖脚本。
