## 页面行为

首页“原典版本”显示版本来源、144页、十八卷及缺跋说明。点击“阅读宋刻本”从《南山经》卷首开始；点击任一经卷直接跳到卷首。阅读器支持上一页、下一页、输入页码、点击书影放大，并可打开当前页的原版PDF。首页另提供原版PDF下载。

阅读器按页加载2600像素宽的WebP书影，避免进入页面就下载609 MiB原件。前后页到边界后禁用，手机使用横向经卷导航。缺失资源、加载失败和元数据错误均显示提示，网络失败可重试。

角色详情优先展示“原文出处与校勘”：版本、经卷、PDF扫描页、左右半页、简体摘录和考据说明。点击“查看原文第N页”打开阅读器。旧 `classic_quote` 以“角色档案引文（待逐字校勘）”保留，释义与创作设定也单列；已核对状态仅适用于出处卡中的摘录。

## 接口与维护

API前缀 `/api/v1/agentapp/shanhaijing`，沿用现有 `{code: 200, data: ...}` 信封和山海经读取权限：

| 方法与路径 | 返回 |
|---|---|
| `GET /editions` | 版本列表、十八卷目录、资源URL及就绪状态 |
| `GET /editions/{edition_id}` | 单个版本；未知ID返回404 |
| `GET /characters/{char_id}/citations` | 角色出处列表；未知角色返回404，未建出处返回空列表 |

清单缺失、格式错误、重复ID、引用版本/经卷不存在或页码越界返回503，不把坏资料伪装成空结果。资源未导入时API仍返回目录，但 `pdf_available` / `preview_available` 为false。就绪判断检查PDF大小、标记中的SHA与页数、全部144个图片文件的存在性；请求时不重复hash609 MiB文件，完整校验在导入阶段完成。

- `app/services/shanhaijing_sources.py`：只读加载、Pydantic校验、引用关联与资源就绪判断。
- `data/shanhaijing/editions.json`：版本元数据；`asset_key`只能是受限slug，客户端不能提交路径。
- `data/shanhaijing/citations.json`：每条记录含 `character_id`、可选 `edition_id` / `chapter_number` / `pdf_page` / `scan_side`、`excerpt`、`note`、`review_status`，可选 `source_url` 为经过HTTP(S)协议校验的外部原文链接。
- `located`必须有版本、经卷、扫描页和摘录；`pending`不允许已核页码；`external`不能关联宋本经卷或页码。
- 引用独立于 `characters.json`，普通角色编辑、重置不写出处文件。一个角色可有多条出处，原有角色与短剧流程保持兼容。
- 前端入口为 `OriginalTextLibrary`、`OriginalTextReader`、`CharacterSources`，由现有图鉴首页和角色详情接入。

编辑清单后运行 `python -m pytest tests/test_shanhaijing_sources.py -q`，并人工核对新增摘录和跳转页。不要用现代通行电子文本直接替代宋本转写。后续OCR应分别保存正文、郭注、原字形、简体检索文本、页/坐标和校勘状态。

## 离线导入和部署

离线准备环境需要Python 3.12+、`pypdfium2`、`Pillow`；它们只用于资料准备，没有增加Web运行时依赖。

```powershell
python -m pip install pypdfium2 Pillow
python scripts/prepare_shanhaijing_edition.py --source output/pdf/shanhaijing-song-1180/song-1180-color.pdf
```

脚本验证SHA-256，复制原件后逐页生成WebP，完成后写 `ready.json`。重复执行会核验原件并复用已生成图片；发现损坏书影时会中止，需要移走该损坏页后重跑。可用 `--target` 指定部署暂存目录。

部署内容：

```text
data/shanhaijing/editions.json
data/shanhaijing/citations.json
data/uploads/shanhaijing/editions/song-1180/
  song-1180-color.pdf
  pages/001.webp ... 144.webp
  ready.json
```

应用复用 `/uploads` 静态映射，Vite已有该路径代理。生产Compose使用 `./data:/app/data`；基础Compose使用 `app_data` 命名卷，需显式复制清单与资源到卷内。原始PDF与派生书影已加入定向Git忽略规则，不会打入JS包；小型JSON清单、代码和导入脚本进入版本管理。无需新端口、环境变量或数据库迁移。

本机服务已验证原件 `Range: bytes=0-15` 返回206和正确的 `Content-Range`；部署到其他环境后仍需验证生产反向代理是否保留Range支持。
