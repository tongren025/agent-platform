# 一人团队：知识到成片的最简操作手册

> 目标不是维护一套漂亮的知识库，而是用最少人工操作稳定产出完整作品。
> 总架构见 [`KNOWLEDGE_ARCHITECTURE.md`](KNOWLEDGE_ARCHITECTURE.md)。

## 1. 只记住四个抽屉

| 你手里的信息 | 放哪里 | 例子 | 不要放哪里 |
|---|---|---|---|
| 当前项目事实 | 制作项目的原始内容、已审批 setting/design/剧本卡片 | 世界观、角色、场景、画风 | 长期记忆、每个员工角色描述 |
| 跨项目专业方法 | 对应数字员工的知识文档 | 分镜 SOP、镜头语言、提示词规范 | 项目卡片 |
| 外部候选资料 | 文章学习、提示词采集 | 参考文章、热门案例 | 项目正典 |
| 用户长期偏好与纠正 | Agent 记忆 | “始终用中文”“先给结论” | 项目知识文档 |

当前版本尚未提供独立的“项目正典空间”。过渡期以制作项目的原始内容和已审批生产卡片为项目权威来源；
发生冲突时修改最上游卡片并重生成下游，不把同一段设定复制进多个员工 `roleProfile`。

## 2. 首次使用：30 分钟完成最小设置

1. 在“数字员工”里只保留真正参与当前作品的角色，通常导演/统筹、编剧、分镜、美术、视频 5 类已经足够。
2. 每个角色最多上传 1–3 份方法文档，文件名用 `岗位-主题-v1.md`，每份只解决一类问题。
3. 打开“知识中心”，确认新文档显示“已索引”或“关键词模式”；两种都可用，“关键词模式”只是没有语义增强。
4. 在“导演 Agent”创建项目，只输入本项目的事实、约束和想达到的观感，不粘贴通用教程。
5. 第一轮 setting/design 卡片生成后人工确认一次；它们成为后续剧本、分镜、图片和视频的上游依据。

不要在开工前批量导入几十篇资料。先用最小知识集跑通一集，只有出现明确质量问题时才补对应岗位资料。

## 3. 每天的生产主路径

```text
导演 Agent
  → 打开正在制作的项目
  → 只执行系统给出的“唯一下一步”
  → 在设定冲突、镜头审片、付费生图/视频时人工确认
  → 其余阶段沿上游卡片继续生成
  → 合成并预览成片
```

日常不要从“知识中心”开始工作。知识中心是支撑区，导演 Agent 和制作项目才是生产主线。

遇到问题时按以下顺序处理：

1. **作品事实错了**：改项目原始内容或最上游 setting/design 卡片，再生成下游。
2. **某岗位方法不稳定**：给对应员工补一份短 SOP，避免把方法塞进项目设定。
3. **系统反复违背个人习惯**：在对话中明确纠正一次，再到记忆库确认是否值得长期保留。
4. **只是想参考新案例**：放到文章学习或提示词采集，不直接升为项目事实。

## 4. 每周 30 分钟维护

建议固定在一集收尾后批量处理：

- 10 分钟：在知识中心看“关键词模式”文档；只有确实需要语义检索时才排查 embedding 配置。
- 10 分钟：删除重复、过时或没有实际帮助的岗位资料；每个岗位尽量不超过 5 份活跃文档。
- 5 分钟：查看 Agent 记忆，删除一次性项目参数和模型自行推断的事实。
- 5 分钟：把本周真正有效的新方法合并回原 SOP，而不是继续新增碎片文件。

如果维护超过 30 分钟，优先停止新增资料，而不是增加标签、审批层级或第二套知识工具。

## 5. 判断有没有达到最终效果

一人团队不以文档数量为目标，而看以下结果：

- 从创意到完整草稿是否始终能看到一个明确下一步；
- 同一角色、场景、画风在剧本、分镜、图片和视频中是否一致；
- 每集需要人工复制粘贴设定的次数是否接近 0；
- 人工主要集中在创意拍板、设定冲突、镜头审片和付费确认；
- 新增资料后，返工或提示词修改次数是否真的下降。

连续两集没有改善的资料应删除或降级为外部参考；连续两集重复出现的问题，才值得进入岗位 SOP 或后续项目正典。

## 6. 当前边界

- `.txt/.md` 是当前真实支持格式；PDF/docx 需要统一解析与状态可见后再开放。
- JSON 模式可零依赖运行；没有 pgvector/embedding 时会显示“关键词模式”，不会阻断生产。
- 当前增量记忆已避免单进程下重复分析完整历史；跨多 worker 的事务游标、持久索引任务与项目正典空间按
  [`plans/KNOWLEDGE_SYSTEM_BLUEPRINT.md`](../plans/KNOWLEDGE_SYSTEM_BLUEPRINT.md) 后续实施。
